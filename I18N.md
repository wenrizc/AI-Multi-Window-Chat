# Internationalization

The extension uses Chrome's `_locales` catalogs with English as the default.
The website reads the same catalogs: Simplified Chinese (`zh`, `zh-CN`,
`zh-SG`, `zh-Hans`) uses `zh_CN`; Traditional Chinese and other unsupported
languages fall back to English. The `common__locale` message identifies the
actual catalog language used for the document's `lang` attribute.
Website URLs can override browser preferences with `?lang=en` or
`?lang=zh-CN`; internal page links preserve the override. Missing website
messages fall back individually to the English catalog.

Pass substitutions as a string, number, or ordered array to `t` (pages) and
`i18nMessage` (TypeScript/background). Object arguments are not supported.
Catalog messages can use `$1`, `$2`, etc., or named placeholders whose
`content` refers to those positions. For example, use
`t('config__statusImported', [addedCount, updatedCount])`. Values are inserted
literally and never interpreted as further placeholders or replacement syntax.

Use `data-i18n` for text and explicit `data-i18n-placeholder`,
`data-i18n-title`, and `data-i18n-aria-label` for attributes. Reserve
`data-i18n-html` for reviewed, static markup from the bundled catalogs.
Tool protocol text remains stable; structured display metadata provides
localized labels without changing what the model receives.

Use **AI Multi-Window Chat / AI 多窗口对话** as the product name,
**provider configuration / 服务配置** for a configured API service, and
**default configuration / 默认配置** for the configuration selected for new chats.
The reasoning panel uses **Reasoning content / 推理内容**, covering both
full reasoning fields and summaries. Keep API field names and model IDs unchanged.

When changing a catalog, update both languages, run `npm run build:website`,
and run the i18n unit tests. They check all production references and catalog
placeholder contracts. The E2E language matrix checks the actual Chrome
fallback behavior alongside the website and verifies explicit-language navigation.
